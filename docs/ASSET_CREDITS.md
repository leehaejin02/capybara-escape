| 도입일 | 2026-08-06 |

**쓰는 범위와 안 쓰는 범위 (2026-08-06 결정)**

- ❌ **안 쓴다**: AI 이미지 생성 파이프라인. 이 도구가 지원하는 프로바이더는 `codex` / `grok`뿐인데
  이 환경에 둘 다 없고, 별도 유료 구독이 필요하다
- 모든 스프라이트는 **우리가 스크립트로 생성**한다 (GDD 8장 "코드/스크립트로 생성" 경로)

**⚠️ 정정 (2026-08-07) — 실제 사용 방식이 당초 계획과 달랐다**

당초 계획은 body 4색 컬러웨이를 **sprite-gen `recolor`로 굽는** 것이었다. 실제로는 다음과 같이 됐다:

- 커밋되는 `scripts/gen-sprites.mjs`는 리컬러를 **순수 JS로 직접 구현**했다.
  이유: (1) 새 의존성 0개 원칙, (2) **심사자가 sprite-gen 없이 `npm ci && npm run build`만으로
  전 과정을 재현할 수 있어야 한다.** 빌드 경로에 외부 파이썬 도구가 끼면 재현성이 깨진다.
- sprite-gen은 대신 **교차검증(QA)에 실제로 사용**했다. `recolor --base capy_body_01.png --spec ...`를
  실행해 우리 JS 출력과 대조한 결과 `capy_body_{02,03,04}` 전부 **디코딩된 raw RGBA가 바이트 단위로 동일**했다.
  → 우리 구현이 검증된 도구와 같은 결과를 낸다는 독립 근거다.

**따라서 저장소의 어떤 산출물도 sprite-gen이 만든 것이 아니다.** 이 도구는 우리 결과가 맞는지
확인하는 데만 쓰였다. 그럼에도 실제로 실행했으므로 출처를 남긴다.

**Apache-2.0 준수**: 저장소에 코드를 포함하지 않고 산출물도 쓰지 않으므로 라이선스 전문 동봉
의무는 발생하지 않는다. 그래도 실행해 사용한 사실을 위와 같이 명시한다.
이후 코드를 벤더링하게 되면 `LICENSE` 전문과 `NOTICE`를 함께 포함해야 한다.

### 시각 레퍼런스 (참고만 함 — 저장소·빌드에 포함되지 않음)

**2026-08-07**: 사용자가 카피바라·고블린 픽셀아트 이미지를 **스타일 레퍼런스로 제시**했다.
`docs/ART.md` §3.1·§3.3의 실루엣 개정은 이 레퍼런스에서 **비례·실루엣 특징·색감 방향만** 취했다.

- **픽셀 복제는 없다.** 레퍼런스의 픽셀 배치를 옮기거나 트레이스하지 않았고,
  개정된 좌표는 전부 `gd`가 우리 16색 팔레트(§1.1)와 32×32 규격에 맞춰 새로 설계한 것이다.
- 레퍼런스 이미지 파일은 **저장소에 커밋하지 않았고 빌드 산출물에도 포함되지 않는다.**
- 따라서 **게임에 포함되는 외부 에셋은 여전히 0건**이다(위 표 그대로).

> 아이디어·스타일 방향은 저작권 보호 대상이 아니지만, 표현(픽셀 배치)은 보호 대상이다.
> 이 구분을 지켰다는 사실을 남기기 위해 여기에 기록한다 (CLAUDE.md 하네스 10·11).

## 런타임 의존성 (Runtime dependencies)

빌드 결과물에 포함되거나 빌드에 필요한 npm 패키지.

| 패키지 | 라이선스 | 용도 |
|---|---|---|
| [phaser](https://github.com/phaserjs/phaser) | MIT | 게임 엔진 (런타임 포함) |
| [vite](https://github.com/vitejs/vite) | MIT | 번들러 (빌드 전용) |
| [typescript](https://github.com/microsoft/TypeScript) | Apache-2.0 | 컴파일러 (빌드 전용) |
| [@types/node](https://github.com/DefinitelyTyped/DefinitelyTyped) | MIT | 타입 정의 (빌드 전용, 런타임 코드 없음) |

CI에서 쓰는 GitHub 공식 액션(`actions/checkout`, `actions/setup-node`)은 MIT이며 빌드 결과물에 포함되지 않는다.
