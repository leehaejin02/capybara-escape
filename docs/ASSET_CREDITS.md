게임에 포함되지 않고 **에셋 제작에만 쓰는** 소프트웨어. 심사자가 게임을 실행할 때는 필요하지 않다.

| 도입일 | 2026-08-06 |

**쓰는 범위와 안 쓰는 범위 (2026-08-06 결정)**

- ❌ **안 쓴다**: AI 이미지 생성 파이프라인. 이 도구가 지원하는 프로바이더는 `codex` / `grok`뿐인데
  이 환경에 둘 다 없고, 별도 유료 구독이 필요하다
- 모든 스프라이트는 **우리가 스크립트로 생성**한다 (GDD 8장 "코드/스크립트로 생성" 경로)

**⚠️ 정정 (2026-08-07) — 실제 사용 방식이 당초 계획과 달랐다**

당초 계획은 body 4색 컬러웨이를 **sprite-gen `recolor`로 굽는** 것이었다. 실제로는 다음과 같이 됐다:

- 커밋되는 `scripts/gen-sprites.mjs`는 리컬러를 **순수 JS로 직접 구현**했다.
  이유: (1) 새 의존성 0개 원칙, (2) **심사자가 sprite-gen 없이 `npm ci && npm run build`만으로
  전 과정을 재현할 수 있어야 한다.** 빌드 경로에 외부 파이썬 도구가 끼면 재현성이 깨진다.
- sprite-gen은 대신 **교차검증(QA)에 실제로 사용**했다. `recolor --base capy_body_01.png --spec ...`를
  실행해 우리 JS 출력과 대조한 결과 `capy_body_{02,03,04}` 전부 **디코딩된 raw RGBA가 바이트 단위로 동일**했다.
  → 우리 구현이 검증된 도구와 같은 결과를 낸다는 독립 근거다.

**따라서 저장소의 어떤 산출물도 sprite-gen이 만든 것이 아니다.** 이 도구는 우리 결과가 맞는지
확인하는 데만 쓰였다. 그럼에도 실제로 실행했으므로 출처를 남긴다.

**Apache-2.0 준수**: 저장소에 코드를 포함하지 않고 산출물도 쓰지 않으므로 라이선스 전문 동봉
의무는 발생하지 않는다. 그래도 실행해 사용한 사실을 위와 같이 명시한다.
이후 코드를 벤더링하게 되면 `LICENSE` 전문과 `NOTICE`를 함께 포함해야 한다.

### 2026-08-08 — 스프라이트·타일을 AI 생성본으로 교체

경위와 스코프 판단은 `docs/DECISIONS.md` **D14**. 요약하면, 기존 스프라이트는
`gd`가 문서에 좌표를 적고 `tech`가 스크립트로 찍는 방식이라 **아무도 결과물을 보지 못한 채**
만들어졌고, 그 품질 한계를 사용자가 두 번 지적해 교체를 결정했다.
**교체 범위는 D14 원안(바닥·고블린·소품)보다 넓다** — 카피바라 3레이어와 `tile_wall` 3종이 추가됐고,
이 둘은 D14-b·D14-d가 명시적으로 제외했던 것이다. 뒤집힌 사유는 **D14-b·D14-d의 🔴 정정 블록과 D14-g**에 있다.

- **생성**: 저장소 소유자(leehaejin02)가 Google Gemini로 직접 생성. 프롬프트는 코디네이터가 작성.
  참고한 시각 레퍼런스는 저장소에 **커밋하지 않았고** 픽셀을 복제하지도 않았다(아래 §시각 레퍼런스와 같은 원칙).
- **원본 보존**: `art-source/ai_*_src.png` — **7장**입니다:
  `ai_capybara_src.png` / `ai_floor_src.png` / `ai_goblin_src.png` / `ai_hat_src.png` /
  `ai_outfit_src.png` / `ai_props_src.png` / `ai_wall_src.png` (2560×2560 래스터).
  여기에 **빌드에 포함되지 않는 참고용** `ai_mockup_reference.png`(AI가 낸 합성 예시) 1장이 더해져
  **이 커밋에 들어간 원본 파일은 8개**다.
  > **정정 2026-08-08** (`verify` 실측): 이 줄은 *"래스터 6장"* 이라고 적혀 있었다. 실제는 7장 + 목업 1장이다.
  > 6장으로 적혔던 이유는 `import-ai-art.mjs`의 시트 목록(floor/wall/goblin/props + capybara)만 세고
  > **`layoutItemSheet()`가 따로 읽는 hat·outfit 시트를 빠뜨렸기 때문**으로 보인다.
- ⚠️ **저장소 크기 대가**: 이 원본 보존으로 저장소가 **약 30MB 늘었다.**
  D14-e가 *"되돌림 비용 0"* 을 성립시키려고 요구한 것이 바로 이 보존이다 — 되돌림 경로
  (`npm run import:art` 재실행 / `npm run gen:sprites` 복원)를 살려 두는 대가로 용량을 지불했다.
  **의도한 거래이고, 숨기지 않고 적어 둔다.** 제출물은 소스 저장소이므로 용량 제한 요건은 없다.
- **수정 내용**: 생성 AI의 출력은 픽셀아트가 아니라 "픽셀아트처럼 보이는 래스터"다
  (카피바라 시트 실측 **고유색 51,953개**). `scripts/import-ai-art.mjs`가 블록 최빈색 축소 →
  칸 구분선 제거 → 색 뭉치기 → 고립 픽셀 제거 → 밝기 평준화 → 발끝 정렬을 거쳐 32×32로 굽는다.
  **`npm run import:art`로 언제든 재현된다.**
- **타이틀 배경 `title_screen.png` (2026-08-08 추가)**: 로고와 게임 제목이 **이미 그려진**
  전면 일러스트다. 원본 `art-source/ai_title_src.png`(1264×848)는 고유색 **118,522개**에
  가로 색 구간 최빈값이 1px이라 **스냅할 픽셀 격자가 없었다** — 스프라이트와 달리 AI가
  픽셀아트 '느낌'으로 그린 매끄러운 래스터다. 그래서 격자를 찾는 대신 우리가 정했다:
  480×320으로 굽고 화면에서 정확히 2배로 띄운다. 240×160은 로고 글자당 17px로 빠듯해
  탈락시켰고(480은 34px), 비정수 배율은 세션 6에서 고친 한글 획 소실 결함을 되살린다.
  이 그림이 들어오면서 `logo_title.png`는 화면에서 쓰이지 않게 됐다(로드는 유지).
- **타이틀 배경 v2 교체 (2026-08-09)**: 사용자가 Gemini로 새로 생성한 그림으로 갈아끼웠다.
  원본 크기가 v1과 같은 **1264×848**이라 변환 경로·수치는 그대로 쓴다 — 코드는 한 줄도
  바뀌지 않았고 `art-source/ai_title_src.png`만 교체한 뒤 `npm run import:art`를 돌렸다.
  **v1 원본은 지우지 않고 `art-source/ai_title_src_v1_superseded.png`로 남겼다** —
  현재 배포본 이전 화면이 어디서 왔는지 추적 가능해야 하기 때문이다.
  재생성 결과 `public/assets/` 중 **`title_screen.png` 한 장만 바뀌었다**(나머지 6개 시트는
  바이트 동일). 파이프라인이 결정적이라는 뜻이라 함께 기록한다.
- **되돌림**: `scripts/gen-sprites.mjs`는 삭제하지 않았다. `npm run gen:sprites`로 기존 코드 생성본이
  그대로 복원된다(D14-e).
- ⚠️ **숲 벽만 예외**: AI가 낸 숲 행은 2·4열(벽이 세로로 이어지는 칸)을 벽이 아니라 흙바닥으로
  그려서 쓸 수 없었다. 재생성 대신 **마을 나무벽을 어둡게 변조해** 숲 벽으로 쓴다.
  초록은 한 픽셀도 넣지 않았다 — `docs/DECISIONS.md` D11-c의 C13(숲에서 초록 = 통과 가능) 유지.

### `logo_title.png` — AI 생성 이미지 고지

타이틀 화면 로고 「이세계 카피바라★」. **이 프로젝트에서 유일하게 코드로 생성하지 않은 에셋**이다.

- **출처**: 저장소 소유자(leehaejin02)가 Google Gemini로 직접 생성했다. 제3자 저작물을 가져온 것이 아니다
- **1376×768 RGBA, 약 2.3MB** — 웹 빌드 기준 큰 편이라 최적화 여지가 있다
- **「AI 활용 기술 문서」에 이 사실을 반드시 명시한다.** 대회 규정은 AI 합성물을 **플레이 영상**에 쓰는 것을 금지하는데, 그건 "실제 플레이 화면"을 위조하지 말라는 취지다. 로고는 게임 내 그래픽 에셋이므로 그 조항의 대상이 아니다.
  다만 **출처를 밝히지 않는 것이 위반**이므로 여기와 기술 문서 양쪽에 남긴다
- ⚠️ **정정 2026-08-08**: 이 줄은 *"나머지 스프라이트·타일·사운드는 전부 코드 생성"* 이라고
  적혀 있었다. **2026-08-08 아트 교체(D14) 이후로는 사실이 아니다** — 스프라이트·타일 23종 중
  **16종이 AI 생성본**이고 7종만 코드 생성이다(위 표 참조). 사운드는 여전히 Web Audio 실시간
  합성이라 외부 에셋 0건이 맞다. 로고 절 안에 있어 D14 갱신에서 누락됐다(`gd` 발견).

**2026-08-07 수정 — 체커보드 배경 알파 제거.** 원본 PNG는 이미지 편집기의 투명 표시 격자가
실제 불투명 픽셀로 구워진 채였다(타이틀 화면에 회색 격자가 그대로 보임). `tech`가
`scripts/fix-logo-alpha.mjs`(무의존, 새 npm 패키지 0개)로 배경에서 flood fill해 알파를 0으로
고쳤다. **원본은 `art-source/logo_title_raw.png`에 그대로 보존**했고, 게임이 로드하는
`public/assets/logo_title.png`만 알파가 바뀐 결과다. 카피바라·방패·글자 등 로고 본체 픽셀은
색이 바뀌지 않았다 — 스크립트 주석에 검증 절차(diff mask 육안 확인·세부 확대 검사·배경 합성 확인)를 남겨 뒀다.

> ⚠️ 대회 규정에 "AI 생성 그래픽 에셋 사용 제한" 조항이 별도로 있는지는 **확인하지 못했다.**
> `docs/SUBMISSION.md`에서 확인한 원문에는 에셋 관련 조항이 *출처·라이선스 명시 필수 / 무단 도용 시 선발 취소* 뿐이었다.
> 제출 전 공식 FAQ를 한 번 더 확인할 것을 권한다.

### 시각 레퍼런스 (참고만 함 — 저장소·빌드에 포함되지 않음)

**2026-08-07**: 사용자가 카피바라·고블린 픽셀아트 이미지를 **스타일 레퍼런스로 제시**했다.
`docs/ART.md` §3.1·§3.3의 실루엣 개정은 이 레퍼런스에서 **비례·실루엣 특징·색감 방향만** 취했다.

- **픽셀 복제는 없다.** 레퍼런스의 픽셀 배치를 옮기거나 트레이스하지 않았고,
  개정된 좌표는 전부 `gd`가 우리 16색 팔레트(§1.1)와 32×32 규격에 맞춰 새로 설계한 것이다.
- 레퍼런스 이미지 파일은 **저장소에 커밋하지 않았고 빌드 산출물에도 포함되지 않는다.**
- 따라서 **게임에 포함되는 외부 에셋은 여전히 0건**이다(위 표 그대로).

> 아이디어·스타일 방향은 저작권 보호 대상이 아니지만, 표현(픽셀 배치)은 보호 대상이다.
> 이 구분을 지켰다는 사실을 남기기 위해 여기에 기록한다 (CLAUDE.md 하네스 10·11).
