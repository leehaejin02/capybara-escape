## 2026-08-06 — 스캐폴딩 단계 착수 전 결정 6건

`director` 라우팅 결과에 대한 사용자 승인. 이 6건은 코드 첫 줄의 구조를 결정하므로
나중에 바꾸면 `playtest`·`verify` 절차가 통째로 흔들린다.

| # | 결정 | 이유 |
|---|---|---|
| D1 | `src/sim` 경계를 **`scripts/check-boundary.mjs` 하나로** 강제 (무의존). `tsconfig.sim.json`과 런타임 크래시는 조건부 보조일 뿐 게이트가 아니다 | 관습으로는 반드시 깨진다. 새 의존성(ESLint 등) 없이 가능한 최대 강도. 검사기가 `npm run sim`과 `npm run build` 양쪽 크리티컬 패스에 있어 개발·배포 흐름에서 자동으로 걸린다 |
| D2 | **`@types/node` 추가 승인** (하네스 8 예외) | `src/tools/sim-cli.ts`가 `process.argv`를 읽어야 한다. 타입 전용이라 번들에 런타임 코드가 들어가지 않는다. **eslint / prettier / vitest / tsx / ts-node는 요청하지 않으며, 요청이 와도 거절한다** |
| D3 | 시뮬 실행 경로 = **tsc 선컴파일** (`tsconfig.sim.json` → `dist-sim/`) | 이 머신은 Node v24.18.1이라 타입 스트리핑으로 `.ts` 직접 실행도 가능하지만, 어차피 `tsconfig.sim.json` 컴파일이 경계 강제 장치(D1의 2차)다. 컴파일을 건너뛰면 장치가 하나 빠진다 |
| D4 | CLI 종료 코드 = `0` 완주 / `1` 사용법 오류·크래시 / `2` `--assert` 미달 | `playtest`는 밸런스 미달 시에도 원자료가 필요하므로 미달을 실패로 보면 안 되고, `verify`는 기계적 게이트가 필요하다. 두 요구를 `--assert` 플래그로 분리한다 |
| D5 | **스텁 시뮬을 이번 단계의 "완료"로 인정** | 게임 규칙 전에 경계를 굳히는 게 목적이다. 착각 방지는 시스템이 한다 — 출력에 `!! STUB` 배너 + JSON `"stub": true` + **`--assert`는 stub인 동안 무조건 exit 2**. 이 플래그는 고블린 FSM·미션·충돌이 실제로 들어올 때 `tech`가 명시적으로 내린다 |
| D6 | **씬 껍데기(S2·S3·S4)를 만들지 않는다.** `BootScene`만 | 스펙 없는 빈 씬은 다음 단계에서 다시 쓰게 되고, "화면 전환은 됐다"는 착시로 진척 판단이 흐려진다 (GDD 10장 MUST 첫 항목이 조기에 체크된 것처럼 보이는 문제) |

### D1 정정 (같은 날, 구현 후) — "3중 장치"는 사실이 아니었다

D1을 처음 쓸 때는 세 장치가 **각각 독립적으로** 경계를 막을 것으로 기대했다.
`tech`가 구현 중 실측으로 그게 사실이 아님을 밝혔고, `verify`가 문서에 남은 과장을 잡아냈다.
**실제로 작동하는 것은 1개뿐이다.**

| 장치 | 기대 | 실측 결과 |
|---|---|---|
| `scripts/check-boundary.mjs` | 1차 | ✅ **유일한 실질 게이트.** 이게 죽으면 아무도 경계를 지키지 않는다 |
| `tsconfig.sim.json` | 2차 | ❌ **막지 못한다.** sim에 `import Phaser from 'phaser'`를 넣어도 `tsc -p tsconfig.sim.json`이 exit 0. TypeScript에 "이 디렉터리에서 이 패키지 금지" 옵션이 없다. `moduleResolution: "Classic"`은 TS7에서 제거됐고, `paths` 리맵은 실패 시 node 해석으로 폴백한다 (둘 다 실측 확인) |
| 런타임 크래시 | 3차 | ⚠️ **조건부.** import한 값을 실제로 참조할 때만 발동한다. 미사용 import는 tsc가 출력에서 지워버려 발동조차 안 한다. **`import type`은 영원히 못 잡는다** |

`tsconfig.sim.json`이 실제로 하는 일은 **컴파일 범위 격리**다 (`src/scenes`·`src/main.ts`가 sim 컴파일 단위에 들어오지 않게 막음). 그건 여전히 가치가 있지만 import 차단은 아니다.

**따라서 `check-boundary.mjs`는 이 프로젝트에서 가장 중요한 파일 중 하나다.** 지우거나 우회하지 않는다.
`npm run sim`과 `npm run build` 양쪽에 걸어 뒀고, 스캔한 sim 파일이 0개면 스스로 exit 1로 실패한다
(폴더가 옮겨졌는데 초록불이 뜨는 게 최악의 실패 모드라서다).

`verify`가 13종 import 형태로 교차 검증했고 오탐·미탐 0건이다 — 타입 전용·동적·`require`·다중행·주석 안 가짜 import 포함.

> 이 정정을 남기는 이유: 문구만 보고 "3중이니 안전하다"고 오판하면, 실제로는 파일 하나에 매달린 경계를
> 무방비로 방치하게 된다. 하네스 15(이상한 걸 발견하면 무조건 말한다)의 적용 사례다.

### 같은 날 — `playtest` 명시적 생략 (하네스: 조용한 생략 금지)

고블린·미션·맵이 없는 상태에서 시뮬을 돌리면 **의미 없는 숫자**가 나온다.
그걸 근거로 남기는 것은 하네스 16을 형식적으로만 만족시키는 가짜 근거이고, 곧 하네스 14 위반이다.
→ 대신 D5의 `stub` 강제 실패를 넣어 **시스템이 스스로 "아직 밸런스 자료가 아니다"라고 말하게** 한다.
`playtest` 최초 호출 시점: 고블린 FSM + 미션 3종 + 이동/충돌이 `src/sim/`에 들어온 직후.
