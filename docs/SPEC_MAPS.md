## 0. 이 문서가 생긴 이유 — 우리가 발주를 잘못 읽었다

사용자의 원래 지시는 **"맵이 3개인데 랜덤하게 나온다"** 였다.
`gd`는 그것을 `SPEC_ZONES.md` §5에서 **한 맵을 세로 3구역으로 나누는 것**으로 해석했고,
§5.1에 *"발주 지시와 남북을 뒤집었다"* 는 각주까지 달았다. **각주를 달았다는 것은 스스로 이상함을
감지했다는 뜻이고, 그때 멈춰서 물었어야 했다.** 사용자가 직접 플레이해 보고 정정했다.

- **GDD 10장 WON'T의 "맵 2개 이상"은 사용자 승인으로 해제됐다** (하네스 6의 이 항목만 풀렸다).
- 무엇을 대신 버리는지는 **GDD 10장 개정본**과 이 문서 §7에 있다 (하네스 7).
- 이 오해가 왜 생겼고 무엇을 규칙으로 만들었는지는 `docs/DECISIONS.md` **D12**.

**이 문서가 `MAP_ROWS`의 유일한 원본이 된다.** `RULES.md` §2.4는 이 문서를 가리키도록 바뀌었다.

| R3 | 어느 맵에 걸려도 **똑같이 클리어 가능**하다 (§4 불변식 + §6 균형 게이트가 이를 강제한다) |

### 1.1 맵 목록

| index | 이름 | 테마 (zone) | 출처 | 구조 |
|---|---|---|---|---|
| **0** | `village` | **고블린 집터** (`ZONE_VILLAGE` = 1) | **기존 맵 재활용 — 한 글자도 바꾸지 않는다** | 4열 × 3행 = 12개 방, 2타일 폭 출입구 |
| **1** | `forest` | **숲** (`ZONE_FOREST` = 0) | 신규 (§3) | 어긋난 나무 덩어리 밭 + 개활 오솔길 |
| **2** | `cave` | **동굴** (`ZONE_CAVE` = 2) | 신규 (§3) | 큰 암괴(직사각 암반) + 3폭 통로 |

**index 0이 기존 맵인 것은 설계다.** 되돌릴 때 `MAPS`를 앞에서 자르면(길이 1) 남는 것이
**이미 2라운드 측정을 통과한 맵**이 된다. 되돌림이 "새 코드 경로"가 아니라 "배열 자르기"다.

### 1.2 기존 맵을 재활용한 이유 — 설계를 3개가 아니라 2개로 줄인다

기존 맵은 세 구역이 섞인다는 전제로 짜였다. **단일 테마로 성립하는지 따로 검산했다.**

- 기존 맵의 **온천 `S` 2패치가 전부 중앙 행**에 있고, 온천은 세 테마 중 **집터**의 소품이다
  (`SPEC_ZONES.md` §5.2가 이미 "온천 2패치가 모두 마을 구역"이라고 적어 뒀다).
  즉 **이 맵을 통째로 집터로 읽는 것이 기존 배치와 가장 잘 맞는다.**
- 구조가 **격자형 방 + 2타일 문 + 널빤지/나무통/건초 소품**이라 인공 구조물 테마와 정합한다.
  숲(유기물)·동굴(암반)보다 집터가 이 격자를 자연스럽게 설명한다.
- 맵 데이터가 0바이트 바뀌지 않으므로 **`src/sim/map.ts`의 기존 단언·기존 측정치가 그대로 유효**하다.

### 1.3 세 맵이 공유하는 것 (= 파리티 장치)

이것들은 **다양성을 위해 흔들지 않는다.** 흔들면 균형 검증 비용이 폭증한다.

| 공유 항목 | 값 | 왜 공유하는가 |
|---|---|---|
| `P` 시작 타일 | **(5, 30)** 좌하단 | 이동 거리 파리티가 자동으로 확보된다. 플레이어가 "좌하단 시작"을 한 번만 배우면 된다 |
| `E` 탈출 타일 | **(46, 3)** 우상단 | 위 동일. `SPEC_ZONES.md` §2.3의 *"탈출 방향과 밝아지는 방향이 일치"* 도 유지된다 |
| 미션 지점 수 | 7 (`MISSION.POINT_COUNT`) | `MISSION_TYPES` 배열(길이 7)을 **맵별로 만들지 않는다** |
| `MISSION_TYPES` | `['M1','M2','M3','M1','M2','M3','M1']` **공유** | 미션 시간 예산(10/8/12초)이 세 맵에서 동일해진다 = 파리티 |
| 고블린 수 | 3 (`GOBLIN.COUNT`) | |
| 순찰로 총 길이 | **168 타일** (48 + 48 + 72) | 세 맵의 "순찰 압력"을 같은 값으로 맞췄다. 우연이 아니라 선택 기준이었다 |
| 수풀 `B` | **3패치 × 2×2 = 12타일** | 은신이 MUST다(GDD 10장). 은신 가용성이 맵마다 다르면 그 자체가 밸런스 축이 된다 |
| 온천 `S` | **2패치 × 2×2 = 8타일** | 시그니처 규칙(시간 2배)이 **어느 맵에서도** 등장한다 |
| 순찰 격자 | `col ∈ {6,18,30,42}` · `row ∈ {7,19,31}` | **협상 대상이 아니다.** 깨지면 고블린 AI와 봇 네비게이션이 동시에 무너진다 |

> **`P`·`E`를 맵마다 옮기지 않은 것은 의도된 보수적 선택이다.** 옮기면 (a) 유예 구역 재검산,
> (b) 이동 거리 파리티 재검산, (c) 도달성 재검산이 맵마다 다시 필요하다. 가용 시간은 **8/8 하루**다.
> 맵의 차이는 **벽 구조·미션 배치·순찰로 배분**이 낸다. 그것으로 충분하다고 판단했다.

### 1.4 맵 선택 절차 (R2의 구체화)

```
라운드 시작 시:
  1) mapIndex = rngInt(0, MAPS.length)      # 라운드 RNG의 **첫 번째** 소비
  2) activeMap = MAPS[mapIndex]
  3) 미션 5/7 선택 (RULES.md §5.6)          # 그 다음 소비
  4) 나머지 초기화
```

- **1)이 첫 소비인 것이 규칙이다.** 순서가 흔들리면 같은 시드가 다른 판을 만든다(RULES §2.5와 같은 이유).
- `MAPS.length === 1`이면 `rngInt`는 항상 0을 돌려주지만 **호출은 그대로 한다.**
  호출을 건너뛰면 1맵 되돌림 시 시드 해석이 달라져 되돌림이 "다른 게임"이 된다.
- **⚠️ 이 변경으로 기존 시드의 판 내용이 전부 달라진다.** D8 이전 측정치(7.0% / 12.9%)는
  **새 측정과 직접 비교할 수 없다.** `playtest`는 3맵 상태에서 기준선을 다시 잡는다.

밸런스를 바꾸라는 게 아니라 **맵별로 나눠서 볼 수 있어야** 한다는 요구다.

## 4. 불변식 — `tech`가 로드 시 **세 맵 전부에** 기계로 단언한다

기존 `assertMapInvariants()`는 좌표를 **하드코딩된 기대표**와 대조했다. 맵이 3개가 되면 그 방식은
표를 3벌 유지해야 한다. **표 대조를 구조 검사로 바꾼다** — 아래는 전부 맵 문자열만 보고 판정된다.

> **적용 대상을 조항마다 같은 줄에 적었다** (D10 규칙). "전 맵"이라 쓴 곳은 `MAPS` 전체다.

| ID | 조건 | 적용 대상 |
|---|---|---|
| **MC1** | `rows.length === 37`, 모든 행의 `length === 50` | 전 맵 |
| **MC2** | `rows[0]`·`rows[36]`이 전부 `#`, 모든 행의 `col 0`·`col 49`가 `#` | 전 맵 |
| **MC3** | `col ∈ {6,18,30,42}`의 `row 1..35`에 `#` 0개 **그리고** `row ∈ {7,19,31}`의 `col 1..48`에 `#` 0개 | 전 맵 — **가장 위험한 항목** |
| **MC4** | `M` 7개 · `G` 3개 · `P` 1개 · `E` 1개 | 전 맵 |
| **MC5** | `B` 12개 · `S` 8개. 각각의 4-연결 성분이 **정확히 2×2 정사각형**이고 성분 수가 `B` 3 / `S` 2 | 전 맵 |
| **MC6** | `P`에서 `#`이 아닌 타일만 밟는 BFS가 **`E`와 7개 `M` 전부와 3개 `G` 전부**에 도달한다 | 전 맵 |

## 5. 아트 — 재작업 0건. 바뀌는 것은 **적용 단위**뿐이다

`SPEC_ZONES.md`의 아트 명세는 **전부 그대로 유효하다.** 이미 구워진 3구역 타일 세트
(`tile_wall` 128×96 / `tile_floor` 128×96 / `tile_bush` 64×96 / `tile_spa` 32×96 / `props` 128×96)를
**한 픽셀도 다시 만들지 않는다.**

| 항목 | 이전 | 이후 |
|---|---|---|
| 구역 판정 | `zoneOfRow(row) = row < 13 ? 0 : (row < 25 ? 1 : 2)` | **`activeMap.zone` (맵당 상수)** |
| 프레임 인덱스 | `zoneOfRow(row) * 4 + variant` | **`activeMap.zone * 4 + variant`** |
| 판별성 조건 C11~C13 | "구역별" | **"맵별"** — 조건식·문턱값(35)·측정 정의 전부 불변 |
| 완료 기준 W1~W9 / P1~P7 / R1~R5 | 그대로 | 그대로 |

**렌더가 오히려 단순해진다.** 행마다 구역을 다시 계산하던 분기가 사라진다.

**주의 1 — 온천이 세 테마 전부에 등장한다.** `SPEC_ZONES.md` §5.5가 *"`tile_spa`의 행 0·2는
행 1과 픽셀 완전 동일하게 굽는다"* 고 이미 정해 뒀으므로 **추가 작업이 0이다.** 그 결정이
여기서 값을 했다.

**주의 2 — `SPEC_ZONES.md` §2.6-c의 규칙은 이제 더 강해진다.**
> **숲에서 초록은 전부 통과 가능하다.**
숲이 **맵 전체**가 되면서 이 규칙의 적용 범위가 1/3에서 1로 늘었다. W8(숲 벽 초록 0px)을
반드시 유지한다. 은신이 MUST인 지금(GDD 10장) 이 규칙이 곧 조작 신뢰성이다.

## 6. 난이도가 세 맵에서 비슷한가 — **판정 문턱을 측정 전에 고정한다**

> ### 🔴 2026-08-07 개정 — **PG2의 처방은 유예됐다** (D13). 문턱값 2.5는 그대로다
>
> 세션 5 실측에서 PG2가 깨졌다(13.6 / 4.0 / 1.7 → 비율 **8.13**). **그러나 맵을 빼지 않는다.**
> 이유는 **§6.2의 "비율이면 자의 편향이 상쇄된다"는 논증이 틀렸기 때문**이다 —
> 상쇄되려면 봇의 결함이 세 맵에 **같은 배율**로 작용해야 하는데, `stuckRuns`가
> **forest 27.6% / village 0.8% / cave 0.0%** 로 갈렸다. 배율이 맵마다 다르다는 직접 증거다.
> **즉 비율도 오염돼 있고, PG2는 판정 근거 자격을 잃었다.**
>
> | | |
> |---|---|
> | **문턱값 `TARGET.MAP_CLEAR_RATE_RATIO_MAX = 2.5`** | **바꾸지 않는다.** 완화가 아니다 |
> | PG2 계산·보고 | **계속한다** |
> | PG2 위반의 기록 | **실패로 남긴다.** `verify`가 정상 실패 처리한다. 숨기지 않는다 |
> | PG2 위반의 **처방(맵 제거)** | **집행하지 않는다** |
> | 대체 판정 | **PG1/PG1b(봇 무관 기하)** + **사람 플레이 게이트 HG1~HG4**(D13-d) |
>
> **유예의 해제 조건**: 봇의 결함 크기가 맵마다 다르다는 증거(`stuckRuns` 격차)가 **사라지면**
> PG2는 다시 판정 근거가 된다. 구체적으로 **세 맵의 `stuckRuns`가 모두 5% 미만**이 되면 그렇다.
> 지금 그걸 만들 시간은 없다(가용일 8/8 하루, MUST 3종 미착수).

세션 4의 반증 게이트(봇 FLEE 가설을 측정 전 기준으로 기각한 절차)와 **같은 방식**이다.
완벽한 균형은 목표가 아니다. 잡아야 하는 것은 **"한 맵만 유독 불가능하다"** 하나다.

> ### 🛑 `playtest`는 **측정만 한다.** D8 밸런스 축 동결은 그대로다.
> 게이트에 걸렸을 때의 처방은 **수치 조정이 아니라 그 맵을 `MAPS`에서 빼는 것**이다.
> 이유는 D8 그대로다 — 봇은 도주를 실행하지 못하고 은신을 활용하는 정책도 없다.
> **고장 난 자로 잰 값에 맞춰 맵을 다시 그리면 봇의 결함이 맵에 영구히 새겨진다.**

### 6.1 사전 게이트 (봇 무관 · 기하만으로 판정 — 구현 직후 `tech`가 계산해 보고)

| ID | 조건 | 문턱 (상수) |
|---|---|---|
| **PG1** | 맵별 `BFS(P → E)` 최단 타일 거리 `d_m`에 대해 `max(d) / min(d) ≤ 1.30` | `TARGET.MAP_PATH_LEN_RATIO_MAX` |
| **PG1b** | 맵별 `BFS(P → M_i)` 7개의 **중앙값**에 대해 `max / min ≤ 1.30` | 동일 상수 |

PG1이 깨지면 **시뮬을 돌리기 전에** 문제 맵을 안다. 여기서 걸리면 §7 되돌림으로 직행한다.

### 6.2 시뮬 게이트 (`--map=N`으로 맵별 분리 측정 · 맵당 6시드 × 200회 = 1200회)

| ID | 조건 | 문턱 (상수) |
|---|---|---|
| **PG2** | 맵별 클리어율 `c_m`에 대해 `min(c) > 0` **그리고** `max(c) / min(c) ≤ 2.5` | `TARGET.MAP_CLEAR_RATE_RATIO_MAX` |
| **PG3** | 맵별 평균 완료 미션 수 `k_m`에 대해 `max(k) − min(k) ≤ 1.0` (개) | `TARGET.MAP_AVG_MISSIONS_SPREAD_MAX` |

**왜 절대 수준이 아니라 비율인가**: 봇의 절대 클리어율은 이미 게임의 값이 아니다(D8).
비율은 **같은 고장 난 자로 세 맵을 잰 것**이라 자의 편향이 상쇄된다. 이게 지금 상태에서
의미가 남는 유일한 비교다.

> 🔴 **위 문단의 마지막 두 문장은 틀렸다 (2026-08-07, D13-c 정정).**
> 상쇄에는 **"편향이 세 맵에 공통일 것"** 이라는 전제가 필요한데 그걸 안 적었고, 실측에서 깨졌다
> (`stuckRuns` 27.6 / 0.8 / 0.0). **PG2는 이 문단을 근거로 삼을 수 없다.** 위 머리말의 유예 조항 참조.

**왜 2.5인가**: 1200회 · 클리어율 10%대에서 시드 간 표준편차가 1.2~1.7%p로 관측됐다(GDD 7장).
2배 차이는 잡음으로 설명되지 않는 크기이고, 2.5는 거기에 한 번의 여유를 준 값이다.
**측정 후에 이 값을 올리지 않는다** — 그건 미달을 통과시키려고 시험을 쉽게 만드는 것이다.

### 6.3 게이트 위반 시의 처방 (측정 전에 확정)

> **개정 2026-08-07 (D13-e) — 처방에 「자르는 방향」을 명시했다.**
> 원문은 *"중앙값에서 가장 먼 맵을 뺀다"* 였다. 표본이 3개면 중앙값은 **가운데 값 그 자체**이고,
> "중앙값에서의 거리"는 **상단 이상치와 하단 이상치를 구분하지 못한다.**
> 실측 {13.6, 4.0, 1.7}에서 median=4.0, 거리는 village 9.6 > cave 2.3 →
> **가장 잘 나온 맵이 제거 대상**이 됐다. PG2가 잡으려던 것은 §6 머리말대로 *"한 맵만 유독
> **불가능**하다"* = **아래쪽 꼬리 하나**인데, 처방이 양쪽 꼬리를 대칭으로 취급하고 있었다.
> **부호 없는 양(거리·편차)으로 처방을 서술하지 않는다.**

| 상황 | 처방 |
|---|---|
| PG1/PG1b 위반 | 위반한 맵을 `MAPS`에서 **뺀다.** 다시 그리지 않는다 |
| PG2의 `min(c) === 0` | 그 맵을 **즉시 뺀다.** "클리어 불가능"은 R3 위반이다 |
| PG2 비율 위반 | **클리어율이 가장 낮은 쪽 이상치**, 즉 `argmin(c)` 맵 **하나**를 뺀다. 남은 둘을 다시 재지 않는다(시간 없음). **`argmax(c)` 맵은 어떤 경우에도 이 처방의 대상이 아니다** |
| PG3 위반 | **보고만 한다.** 완료 미션 수는 클리어율의 파생 지표라 독립 게이트로 쓰지 않는다 (`TARGET.AVG_HITS_*`와 같은 논리) |

**PR-V. `MAPS[0]` `village`는 어떤 경우에도 PG2 처방으로 제거되지 않는다.**
§1.1이 *"`MAPS[0]`은 항상 되돌림 기준선"* 이라고 정한 것의 필연적 귀결이다 —
**되돌림 기준선이 제거되면 되돌릴 곳이 없어진다**(D12-d의 설계 의도인데 §6.3에 안 적혀 있었다).
`village`가 `argmin(c)`로 나오는 상황은 처방을 집행하지 않고 **§7 되돌림 판단으로 올린다.**
(PG1/PG1b 위반과 `min(c) === 0`은 별개다. 그건 R3 위반이므로 대상 맵이 무엇이든 뺀다.)

> **⚠️ 위 표의 「PG2 비율 위반」 행은 2026-08-07 현재 유예 상태다** — §6 머리말 참조.
> 방향을 고쳐 둔 것은 유예가 해제됐을 때(세 맵 `stuckRuns` < 5%)를 위해서다.

### 6.4 이 절이 판정하지 않는 것

- **재미·체감·"어느 맵이 더 좋은가"** — 판정 불가능한 기준이므로 게이트로 쓰지 않는다.

  그때 **어느 맵이 나왔는지**를 WORKLOG에 같이 적는다. 추가 비용 0.

### 6.5 사람 플레이 게이트 HG1~HG4 (PG2 유예의 대체 판정 — 기준 원본은 **D13-d**)

  맵 선택 UI는 WON'T이므로 **세 맵이 다 나올 때까지 반복**하되 상한 **10판 또는 25분**.

## 7. 되돌림 경로 — **8/8 안에 못 끝나면 1맵으로 돌아간다**

가용 시간은 **8/8 하루**뿐이고 **8/9는 MUST(영상 + PDF 2종)에 잠긴다.**

```
MAPS = [village, forest, cave]     ← 목표
MAPS = [village, forest]           ← 동굴만 게이트 위반
MAPS = [village]                   ← 되돌림 (게임은 그대로 돌아간다)
```

| ID | 조건 |
|---|---|
| **F-1** | `MAPS.length === 1`이어도 **코드 경로가 하나다.** 맵 개수로 분기하는 `if`를 만들지 않는다 |
| **F-2** | 되돌림은 **배열에서 원소를 빼는 것**으로 끝난다. 다른 파일을 고쳐야 하면 F-1 위반이다 |
| **F-3** | **8/8 종료 시점**에 MC1~MC13 + PG1/PG1b + **HG1~HG4**(§6.5)가 전부 통과하지 않았으면 `MAPS = [village]`로 되돌리고 종료한다. 판단 지점을 사람이 기억하지 않아도 되도록 **날짜로 고정한다** (D8-b가 쓴 방식과 같다) |

> **2026-08-07 상태 (D13)**: MC1~MC13 통과, PG1/PG1b 통과, **PG2 위반이나 처방 유예**(§6 머리말),
> **HG는 8/8에 집행 예정.** 따라서 지금 `MAPS`는 **길이 3 그대로**다.
> **F-3의 날짜 고정은 유지된다** — 판정 항목에서 PG2가 빠지고 HG가 들어왔을 뿐이다.
> 되돌림 경로 자체는 철거하지 않는다. 쓰지 않았을 뿐이다.

## 9. 실측이 아닌 것 (하네스 14)

**`gd`는 새 맵 2개를 플레이해 본 적이 없고, 렌더해서 본 적도 없고, 시뮬을 돌려 본 적도 없다.**

| 항목 | 상태 |
|---|---|
| §3의 ASCII 두 장 | **손으로 조립했다.** 행 길이·격자 열/행·좌표를 열 단위로 손검산했지만 **파서에 넣어 본 적이 없다.** MC1~MC13이 이걸 잡으라고 있는 것이다 |
| §4.1의 벽 수(304 / 315)·통행 타일 수 | **행 단위로 센 값**이다(정정: 설계 합산 307 → 실제 304). 다만 `gd`가 손으로 센 것이고 파서가 센 것이 아니다. **MC12가 실측한다** |
| MC6(BFS 연결성) | **미검증.** 손으로는 "격자 4열 + 3행이 전부 열려 있으므로 모든 방이 격자에 붙는다"까지만 논증했다. **논증이지 실행이 아니다** |
| PG1의 경로 길이 | **미계산.** `P`(5,30)→`E`(46,3) 맨해튼 71은 벽을 무시한 하한이다. 실제 BFS 값은 `tech`가 처음 잰다 |
| 세 맵의 난이도가 비슷한가 | **미측정.** 그래서 §6이 문턱을 **측정 전에** 고정했다 |
| 숲 맵의 **짧은 은폐물만으로 충분한 엄폐가 되는가** | **이번 설계 최대의 베팅.** 3×2 덩어리(96×64px)와 시야 반경 140px의 관계는 계산해 보지 않았다. PG2가 이걸 잡는다 |
| 새 맵이 각각 "숲"·"동굴"로 **보이는가** | **미확인.** 판정은 코디네이터 육안 **1회**. 실패해도 §8대로 아트를 다시 만들지 않는다 — 그 맵을 빼거나 그대로 낸다 |
