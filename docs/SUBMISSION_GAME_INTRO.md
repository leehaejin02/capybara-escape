## 1. 어떤 게임인가

> **이세계에 떨어진 카피바라가 고블린의 서식지에 떨어졌다. 살아남을 수 있을 것인가.**

플레이어는 카피바라 한 마리다. 맵 좌하단에서 시작해 **우상단 탈출구**로 나가야 하는데,
탈출구는 **미션 5개를 끝내기 전에는 열리지 않는다.** 맵에는 고블린 3마리가 순찰하고 있고,
그들의 시야에 들어가면 추격당한다.

미션은 배선을 잇거나, 온천 온도를 맞추거나, 점멸 순서를 외우는 짧은 미니게임이다.
그리고 **미션을 하는 동안 카피바라는 한 발짝도 움직일 수 없다.**

## 2. 코어 루프 — 설계의 중심 한 줄

```
탐색(어디에 미션이 있나) → 이동(고블린 시야 회피) → 미션 수행(그동안 무방비)
   → 발각 → 도주 / 은신 → 복귀 → 반복 → 5개 완료 → 탈출구 개방 → 탈출
```

### 이 게임의 긴장은 **「미션 중에는 움직일 수 없다」** 하나에서 나온다.

이건 여러 재미 요소 중 하나가 아니라 **설계의 중심**이다. 기획서(`docs/GDD.md` 2장)에
*"이 한 줄이 이 게임의 전부다"* 라고 못박아 두고, 4일 내내 이 문장에 어긋나는 제안을
거절하는 기준으로 썼다. 파생된 결정 세 가지:

| 결정 | 이 문장에서 어떻게 나왔나 |
|---|---|
| **고블린 추격 속도(75) < 플레이어 속도(90)** | 계속 움직이는 플레이어는 원리적으로 따돌릴 수 있어야 한다. 그래야 플레이어가 통제하는 변수가 *"언제 멈춰 설까"* 하나로 남는다 |
| **미션 중 피격 시 진행도 0** | 멈춰 서는 선택에 대가를 붙인다 |
| **자발적 중단(이동)도 진행도 0** | 도망갔다 돌아와 이어서 하는 게 공짜면 "언제 시작할지"의 판단 비용이 사라진다 |

> 반대로 **커스터마이즈는 성능에 전혀 영향을 주지 않는다.** 밸런스 축을 늘리지 않기 위한 의도적 결정이다.

## 3. 게임 방법 · 종료 조건 · 실행 방법

### 3.1 목표

**제한시간 180초 안에 미션 5개를 완료하고 우상단 탈출구로 나가는 것.**
탈출구는 미션 5개를 끝내기 전에는 열리지 않는다. 맵을 순찰하는 고블린 3마리의
시야에 들어가면 추격당하고, 접촉하면 체력이 깎인다.

### 3.2 조작

| 조작 | 키 |
|---|---|
| 이동 | **방향키** 또는 **WASD** |
| 상호작용 (미션 시작 / 탈출) | **E** |
| 대시 | **Shift** |
| 음소거 | **M** |

미니게임별 입력:

| 미션 | 입력 |
|---|---|
| M1 배선 잇기 | 마우스 **드래그** (켜진 단자 → 같은 색 단자) |
| M2 온천 온도 | **Space** 또는 클릭 (바가 초록 구간에 있을 때) |
| M3 순서 기억 | **클릭** 또는 **키 1~4** (점멸한 순서대로) |

메뉴: 타이틀은 **클릭**으로 시작, 커스터마이즈는 **↑↓** 항목 선택 · **←→** 변경 · **Space**(또는 `[입장]` 클릭)로 확정,
결과 화면은 **R** 로 재시작.

### 3.3 종료 조건

한 판은 **반드시 아래 셋 중 하나로 끝난다.** 끝나면 결과 화면(S4)이 뜨고 `R`로 재시작한다.

| 종료 | 조건 | 결과 화면 문구 |
|---|---|---|
| **승리** | 미션 5개 완료 후 **탈출구 도달** | 「탈출 성공!」 |
| **패배** | **제한시간 180초 소진** | 「시간 초과」 |
| **패배** | **체력 0** (고블린 접촉 3회) | 「체력 소진」 |

결과 화면에는 **남은 시간 · 완료 미션 수 · 피격 횟수**와 내가 꾸민 카피바라가 표시된다.

### 3.4 실행 방법

**심사자용 — 설치할 것이 없습니다.**

> ### ▶ https://leehaejin02.github.io/capybara-escape/
>
> 링크를 열면 바로 실행된다. **설치·계정·플러그인·다운로드가 필요 없다.**
> 데스크톱 브라우저(Chrome·Edge·Firefox 최신 버전) 기준이며 키보드와 마우스를 쓴다.
> 소리가 있으므로 스피커나 헤드폰을 켜는 것을 권한다(게임 안에서 **M** 키로 음소거).

**소스에서 직접 실행하려면** (선택 사항 — 심사에 필요하지 않다)

```
git clone https://github.com/leehaejin02/capybara-escape
cd capybara-escape
npm ci          # 의존성 설치 (phaser / vite / typescript / @types/node)
npm run dev     # 개발 서버 실행 → 안내되는 localhost 주소를 브라우저로 연다
```

정적 파일로 빌드하려면 `npm run build` (산출물은 `dist/`).
헤드리스 시뮬레이터는 `npm run sim`으로 돌린다 — 브라우저 없이 게임 규칙만 실행된다.

**Node.js 24**에서 동작을 확인했다(GitHub Actions 배포 워크플로도 Node 24를 쓴다).
그보다 낮은 버전은 시험하지 않았다. **유료 라이선스가 필요한 도구는 없다.**

## 5. 주요 기능

### 5.1 커스터마이즈 120조합 — 인게임과 결과 화면에 그대로 나온다

**몸 4 × 옷 5 × 모자 6 = 120조합.** 세 장의 32×32 스프라이트 시트를 **런타임에 3레이어로 겹쳐**
단일 텍스처로 굽는다(`RenderTexture` 1회 합성). 미리 120장을 만들어 둔 것이 아니다.

고른 카피바라는 **인게임 플레이어 스프라이트와 결과 화면에 그대로 반영된다.**
반영되지 않으면 커스터마이즈가 존재할 이유가 없으므로, 이 항목은 완료 기준(`GDD` 11장 2번)에
넣고 검증 대상으로 삼았다.

### 5.2 미션 3종 — 하는 동안 움직일 수 없다

맵에 미션 지점이 **7곳** 있고, 매 판 그중 **5곳이 무작위로 활성화**된다(각 타입 최소 1개 보장).
지점에 다가가 `E`를 누르면 미니게임 오버레이가 열린다.

| ID | 이름 | 방식 | 시간 예산 |
|---|---|---|---|
| M1 | 배선 잇기 | 좌우 색 4쌍을 드래그로 연결 | 10초 |
| M2 | 온천 온도 맞추기 | 움직이는 바를 초록 구간에서 정지 ×3 | 8초 |
| M3 | 순서 기억 | 4개 아이콘이 점멸한 순서대로 입력 | 12초 |

**미션 중에는 이동·회피가 불가능하고, 고블린은 계속 움직인다.**
그 사이 피격당하면 **진행도가 0으로 돌아간다.** 이동 키를 눌러 스스로 빠져나와도 마찬가지다.

### 5.3 고블린 3마리 — 상태 기계와 벽 차폐 시야

```
PATROL ──(시야 내 감지)──> CHASE ──(시야 이탈 3초)──> SEARCH ──(5초)──> PATROL
                              └──(접촉)──> ATTACK ──(쿨다운 1초)──> CHASE
```

- 시야는 **반경 140px · 각도 90°의 부채꼴**이고, **벽에 가려지면 보이지 않는다**(레이캐스트).
  벽 뒤로 돌아 들어가면 추격이 3초 뒤 풀린다.
- 순찰 60px/s · 추격 75px/s. **플레이어 기본 90px/s보다 느리다** — §2의 불변식이다.
- 경로탐색(A*)은 쓰지 않는다. 직선 추격 + 벽 슬라이딩 + 짧은 우회 커밋이고,
  막힌 상태가 이어지면 SEARCH로 강제 이탈해 "벽에 영원히 끼는" 실패 모드를 시간으로 잘라낸다.

### 5.4 은신 — 온천은 시간이 2배로 흐른다 (시그니처 규칙)

맵의 **수풀**과 **온천**에 들어가면 고블린의 감지 대상에서 **제외된다.**
단, **온천 안에 있는 동안 제한시간이 2배 속도로 흐른다.**

즉 은신처는 두 종류이고 성격이 정반대다.

| 은신처 | 감지 | 시간 |
|---|---|---|
| 수풀 | 제외 | 1배 |
| **온천** | 제외 | **2배** |

안전과 시간이 정면으로 맞바꿔진다. 카피바라의 "느긋함"을 규칙으로 바꾼 장치이고,
이 게임에서 **의도적으로 하나만 둔 시그니처 규칙**이다.

### 5.5 맵 3종 무작위 — 밸런스 축이 아니라 리플레이성 장치다

매 판 시작 시 **숲 / 고블린 집터 / 동굴** 중 하나가 무작위로 뽑힌다(선택 UI 없음, 각 50×37타일 = 1600×1184px).

세 맵은 다음을 **전부 공유한다**: 시작 위치 · 탈출 위치 · 미션 지점 7곳 · 고블린 3마리 ·
순찰로 총 길이 168타일 · 수풀 3패치 · 온천 2패치 · 내부 벽 수 ±10% 이내.

**맵마다 속도·시야·제한시간을 다르게 하지 않는다.** 맵이 밸런스 축이 되면 검증해야 할
조합이 3배가 되기 때문이다. 세 맵의 차이는 **벽 구조와 시야가 끊기는 방식**뿐이다 —
숲은 짧은 은폐물이 흩어져 있고, 동굴은 큰 암괴가 통로 단위로 시야를 끊고,
집터는 격자형 방과 2타일 폭 출입구다.

맵 데이터의 불변식 13개(격자 개통 / 도달성 / 미션 간 최소 거리 / 시작 지점 유예 구역 등)는
**게임 로드 시 코드가 기계적으로 단언**한다. 손으로 그린 맵이 규칙을 어기면 실행이 실패한다.

## 6. 기술 스택

**Phaser 3 + TypeScript + Vite**, GitHub Pages 정적 배포. 링크 하나로 즉시 실행된다.

- **외부 의존성 4개뿐**: `phaser`(MIT) / `vite`(MIT) / `typescript`(Apache-2.0) / `@types/node`(MIT).
  전부 무료이고, 심사자가 추가 비용 없이 `npm ci && npm run build`로 재현할 수 있다.
- **게임 규칙(`src/sim/`)은 Phaser를 import하지 않는다.** 브라우저 없이 Node에서 돌아가며,
  `npm run sim`으로 헤드리스 시뮬레이션을 실행할 수 있다. 이 경계는 빌드 경로에 걸린
  정적 스캐너(`scripts/check-boundary.mjs`)가 강제한다.
- **밸런스 수치는 `src/config/balance.ts` 한 파일에만 있다.** 속도·시야·제한시간·쿨다운을
  코드에 직접 쓰지 않는다.

설계 배경과 에이전트 파이프라인은 제출물 4번 `docs/SUBMISSION_AI_TECH.md`에 있다.

| 그 외 마커·수풀·온천 타일 | **우리 코드가 생성** (`scripts/gen-sprites.mjs`) |
| 사운드 | **오디오 파일 0건.** BGM·효과음을 **Web Audio API로 실시간 합성**한다 |
| **제3자에게서 가져온 에셋** | **0건** |
| 폰트 | 브라우저 기본 스택만 사용. 웹폰트 파일 0건 |

생성 AI의 출력은 픽셀아트가 아니라 "픽셀아트처럼 보이는 래스터"였다(카피바라 시트 실측 **고유색 51,953개**).
그대로 축소하면 안티에일리어싱 얼룩이 픽셀 잡음으로 굳으므로, 변환 스크립트가
**블록 최빈색 축소 → 칸 구분선 제거 → 색 뭉치기 → 고립 픽셀 제거 → 행 밝기 평준화 → 발끝 정렬**
6단계를 거쳐 32×32로 굽는다. 원본 래스터도 저장소에 보존해 언제든 재현된다.

파일 단위 출처·라이선스·수정 내역은 **`docs/ASSET_CREDITS.md`** 에 전부 기재돼 있다.

## 10. 이 문서가 주장하지 않는 것

제출물 4번과 같은 방식으로, **확인하지 못한 것을 확인한 것처럼 쓰지 않기 위해** 이 절을 둔다.

| 주장하지 않는 것 | 실제 상태 |
|---|---|
| **"밸런스가 맞다"** | 기획서 완료 기준 7번(**봇 클리어율 35~55%**)은 **미달이며, 미달인 채로 제출한다.** 최신 실측은 맵별 **13.6 / 4.0 / 1.7%** (맵당 1200회). 원인은 게임 밸런스가 아니라 **측정 기구(시뮬레이션 봇)의 고장**으로 진단됐다 — 봇이 "도망친다"를 실행하지 못한다(이론 이격 속도 15px/s 대비 실측 2.2px/s). 그래서 **고장 난 자에 맞춰 게임 수치를 깎기를 거부**했고, 그 판단 기록이 `docs/DECISIONS.md` D8과 제출물 4번 §7에 있다 |
| **"3분 안에 아슬아슬하게 클리어된다"** | 사람 기준 난이도는 **측정된 적이 없다.** 위 수치는 봇의 값이고, 사람의 값이 목표 대역의 위인지 아래인지조차 모른다 |
| **"조작감이 좋다" / "미니게임이 잘 만들어졌다"** | **재미·조작감을 사람이 평가한 적은 없다.** 2026-08-09에 맵 3종을 각 1판씩 사람이 끝까지 플레이해 **미션 14개를 완료**했고(`balance.ts`의 `MIN_PER_TYPE: 1`이 매 판 각 타입 1개 이상을 보장하므로 **M1 마우스 드래그를 포함해 3종 모두 실제로 수행됐다**), 진행 불능은 관측되지 않았다. 그러나 그것은 **동작 확인이지 재미의 근거가 아니다** |
| **"재미있다"** | 판정 가능한 기준이 아니므로 이 문서는 재미를 주장하지 않는다. 무엇을 하는 게임인지만 설명했다 |
| **"세 맵의 난이도가 비슷하다"** | 맵 간 클리어율 비율 게이트(문턱 2.5)는 **깨졌다**(비율 8.13). 다만 그 판정 근거가 봇이라 **처방을 집행하지 않고 유예**했다. 기하 게이트(경로 길이 비율 ≤ 1.30)는 통과했다 |
| **"모든 실기기에서 정상 렌더된다"** | 개발 머신의 `devicePixelRatio`는 1.1 하나뿐이었다. 다른 DPR(예: 2.0 레티나)에서의 동작은 **계산값이지 실측이 아니다** |

**미달을 넓혀서 통과시키지 않았다.** 목표 지표(35~55%)는 한 번도 완화하지 않았고,
지금도 저장소의 완료 기준에 그대로 남아 정상적으로 실패 처리된다.
왜 맞추기를 거부했는지는 제출물 4번 「AI 활용 기술 문서」에 자세히 적었다.
